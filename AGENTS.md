# simplefin-sdk

Typed SimpleFIN clients for Go and TypeScript, generated from one spec (`spec/simplefin.yaml`). Go module `github.com/6cclab/simplefin-sdk`, npm package `@6cclab/simplefin`.

## Layout
- `spec/simplefin.yaml`: source of truth. `spec/golden/` and `spec/malformed/`: fixtures shared by both SDKs.
- `cmd/simplefin-gen`: generator; `cmd/canonicalize`: Go side of the cross-language check. `internal/ir`, `internal/gen`: spec model and template view.
- `templates/{go,node}`: per-language templates (`docs/PORTING.md` for adding a language).
- `sdk/go`, `sdk/node`: generated files plus hand-written HTTP client. `go.work` joins the root and `sdk/go` modules.

## Commands
- `go run ./cmd/simplefin-gen generate --lang go|node`, `go run ./cmd/simplefin-gen verify`
- `go vet ./... && go test ./internal/...` (root; ci.yml generator job)
- `(cd sdk/go && go vet ./... && go test ./...)`
- `(cd sdk/node && npm ci && npm run build && npx tsc -p tsconfig.json && npm test)` (ci.yml node-sdk job)
- `./scripts/cross-language-check.sh`: Go and Node must agree on every fixture.
All from README "Developing" and `.github/workflows/ci.yml`.

## Conventions
- Never edit files with the `Code generated by simplefin-gen. DO NOT EDIT.` header; change the spec or templates, regenerate, commit the output. CI `verify` fails otherwise.
- Amounts stay strings, never floats. Access URLs embed Basic Auth: split into an Authorization header and keep out of every error message.
- v1 responses are normalized into the v2 shape; unknown wire fields are captured in `unknown`, not dropped.
- No retries, backoff or rate limiting by design; do not add them (README).
- Node tests import from `dist/`, so build before typechecking or testing.

## Gotchas
- `docs/SPEC-DIFF.md` lists where this SDK deliberately differs from the SimpleFIN spec.
- The upstream spec is `2.0.0-draft`; the API is pre-1.0.

## Done means
- Everything in Commands passes: generator `verify`, root vet/tests, both SDK suites, and
  `./scripts/cross-language-check.sh` (CI `ci.yml` runs the same jobs).
- Spec or template changes are committed together with the regenerated output.
- Commits go straight to `main` (no PRs in history).
